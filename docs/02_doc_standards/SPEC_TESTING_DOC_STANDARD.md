# 算法测试与 QA 验证文档书写工程规范 (SPEC_TESTING_DOC_STANDARD.md)

> **适用范围**：存放在各模块下的 `docs/TESTING.md` 以及全局 `docs/03_testing_qa/`。  
> **核心验收标准**：**“清晰定义测试方法学、测试用例输入预期映射、不变量断言标准与失效排查指南，绝不能只有测试命令”**。

---

## 1. 算法测试文档必须包含的 5 大核心章节

```markdown
# [模块名称] 测试与质量保证规范 (TESTING.md)

## 1. 测试设计策略与方法学 (Test Strategy & Methodology)
- 阐明本模块适用的测试策略：等价类划分、极值边界分析、物理守恒断言、PRNG 确定性可复现性验证、蜕变测试。

## 2. 测试运行环境与样本夹具 (Fixtures & Environment)
- 详细说明被测模块在 Node.js 环境下的运行前置条件；
- 列明依赖的样本图片或数据结构（如 examples/photo-fixture.png 的分辨率、像素格式与用途）。

## 3. 测试用例逐项深度解析 (Test Suite Breakdown)
- 必须逐个拆解该测试文件中的每一个具体测试用例（test('...')）：
  - **测试用例名称**：与代码中的 test(...) 字符串 100% 一致；
  - **测试目的与覆盖逻辑**：验证哪一个函数、哪一个边界条件；
  - **输入参数与状态设定**：具体的输入对象、数值；
  - **预期物理/数学不变量 (Invariants)**：如“未暴露区域刻深严格为 0”、“线条坐标绝对偏差 <= 1e-4”；
  - **关键断言实现语句**：摘录核心 assert 语句（如 assert.equal, assert.ok）；
  - **容差标准与验收阈值**：如浮点比较的 delta 容差。

## 4. 性能与基准测试阈值 (Performance Thresholds)
- 给出该模块在标准分辨率（如 1500x1100 2K 或 1800x1320）下的最大允许耗时上限（Budget）与内存占用上限。

## 5. 故障排查与断言失效诊断指南 (Troubleshooting & Diagnosis)
- 列出常见的测试失败场景、可能原因分析及对应的代码排查定位入口。
```

---

## 2. 编写质量红线
- ❌ 严禁出现“运行 npm test 即可”作为整个测试文档的全部内容；
- ❌ 必须明确写出每一个用例的断言物理意义（例如为什么深度必须大于等于 0 且小于等于 1.0）；
- ❌ 引用的测试文件必须在仓库物理存在并能通过 `npm test` 跑通。
