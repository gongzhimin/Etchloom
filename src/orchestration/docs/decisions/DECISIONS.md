## 2. 决策记录

### DEC-ORCH-001: 调度中枢采用中枢协调者模式并杜绝像素算法

- **日期**：2026-10-08
- **状态**：Accepted
- **上下文**：初期设计中编排层容易演变为“杂物桶”，直接内嵌滤镜或部分绘制辅助逻辑，导致与核心算法职责模糊。
- **决策**：严格限定 `orchestration` 仅负责调度、防抖、缓存、生命周期与文件导出，严禁包含任何具体像素与数学滤波算法。
- **后果**：模块职责纯粹单一，易于独立单元测试与跨环境移植；图像处理算子全部收归 `core`。
- **替代方案**：将调度直接内置在 UI 控制器中（导致 UI 层过于臃肿且不可在无头环境复用，被否决）。

### DEC-ORCH-002: 异步任务调度引入 AbortController 抢占信号

- **日期**：2026-10-09
- **状态**：Accepted
- **上下文**：用户连续拖动滑块时，若前序长耗时计算不中断，将造成大量的无用后台排队计算，显著阻塞 UI 主线程。
- **决策**：`TaskScheduler` 为每次调度分发标准 `AbortSignal`，新任务到达时立即主动 abort 前序任务，底层算子在阶段间歇检查并快速退出。
- **后果**：高频调参场景下计算吞吐大幅下降，响应敏捷度大幅提升；需要底层算子配合感知取消信号。
- **替代方案**：使用全局布尔标记 `isCancelled`（多并发任务交替时易产生竞态条件，被否决）。

### DEC-ORCH-003: 增量缓存采用 32-bit DJB2 确定性哈希链

- **日期**：2026-10-10
- **状态**：Accepted
- **上下文**：需要毫秒级判定 5 阶段管线中哪一个阶段的参数发生变化，传统的深度对象比对在大参数树下耗时较长。
- **决策**：采用标准化规范字符串与 32-bit DJB2 位移哈希，每阶段哈希依赖前序哈希，构建轻量级哈希链。
- **后果**：5 阶段失效判定在 0.3ms 内完成，哈希冲突率极低；对象序列化时需做规范键排序。
- **替代方案**：SHA-256 加密哈希（因属于非加密场景且在浏览器端异步开销过大被否决）。
