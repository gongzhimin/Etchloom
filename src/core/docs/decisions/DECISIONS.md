### DEC-CORE-001: 物理网格采用扁平一维 TypedArray 连续内存布局

- **日期**：2026-10-08
- **状态**：Accepted
- **上下文**：虚拟铜版网格包含槽深、裸露、毛刺与掩膜 4 组场，若使用嵌套二维数组 `array[y][x]`，会产生数百万小对象开销并频繁引发 GC 顿卡。
- **决策**：使用连续一维 `Float32Array(width * height)` 与 `Uint8Array(width * height)`，通过 `index = y * width + x` 访问。
- **后果**：大幅提升缓存命中率，压印与酸蚀解算速度提升 8 倍以上；调用方需要注意正确解算一维索引。
- **替代方案**：使用二维 JS Array（因 GC 严重退化被否决）。

### DEC-CORE-002: Jobard-Lefer 流线空间散列碰撞桶设计

- **日期**：2026-10-09
- **状态**：Accepted
- **上下文**：流线排线积分过程中需要反复检测新采样点与已有流线的欧氏距离，传统 $O(N^2)$ 遍历导致高分辨率下排线严重超时。
- **决策**：引入网格尺寸等于流线分离距离 $d_{\text{sep}}$ 的空间散列桶，碰撞检测仅在当前桶及相邻 8 邻域桶内进行。
- **后果**：单点碰撞检测降为 $O(1)$ 常数时间，1024x1024 画布排线解算在 120ms 内完成。
- **替代方案**：四叉树 (QuadTree) 空间索引（因为节点动态插入与重新平衡开销过大被否决）。

### DEC-CORE-003: 核心离散计算与 DOM 环境彻底解耦

- **日期**：2026-10-10
- **状态**：Accepted
- **上下文**：管线早期实现混入了浏览器 `HTMLCanvasElement` 与 `OffscreenCanvas`，导致核心代码无法在 Node.js 环境及独立无头 Worker 中进行自动化测试。
- **决策**：核心离散管线算子输入输出均抽象为 `PixelBuffer { width, height, data: Uint8ClampedArray }`，所有 DOM/Canvas 操作下沉或剥离至 UI 适配层。
- **后果**：核心算子可在 Node.js 测试套件与多线程 Worker 中无缝复用；UI 层需负责将 Canvas 转换为连续内存。
- **替代方案**：在 Node.js 环境引入 `canvas` 原生 C++ 依赖包（因跨平台编译复杂性被否决）。

### DEC-CORE-004: 虚拟铜版酸液反应动力学有效速率因子定标与尺寸泛化

- **日期**：2026-10-10
- **状态**：Accepted
- **上下文**：独立物理仿真器 `acid-simulator.js` 未注入 0.4x 物理反应标定常数，导致计算深度比实际物理秒深 2.5 倍；`VirtualPlateEngine` 缺少自定义长宽比分配能力。
- **决策**：在 `simulateAcidBite` 统一引入 $\Delta t_{\text{eff}} = \Delta t \times 0.4$；在 `allocatePlate` 扩充可选 `height` 参数以无缝兼容非 3:2 原图长宽比。
- **后果**：无头物理仿真与全工坊物理模型完全统一（10 秒腐蚀标准深度 0.1044），消除了物理分裂现象。
- **替代方案**：修改单测断言迎合错误的 2.5x 速率（违反“发现即修”与物理客观规律，被否决）。
