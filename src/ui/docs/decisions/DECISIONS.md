## 2. 决策记录

### DEC-UI-001: 界面采用亚麻纸白与鼠尾草绿莫兰迪极淡美学配色

- **日期**：2026-10-08
- **状态**：Accepted
- **上下文**：莫兰迪古典铜版画创作需要一种沉静、低饱和度、专注纸面与刻线质感的视觉氛围，传统的深色暗黑模式或高饱和商业设计与版画主题不协调。
- **决策**：选定亚麻纸白基底 (`#faf8f5`)、鼠尾草绿主色 (`#536957`)、柔和暖炭灰文字 (`#2a2b2a`) 与细微纸纤维纹理，配合宽幅橡木画框。
- **后果**：视觉质感大幅提升，符合艺术品调性；需精心调校文字对比度以严格满足 WCAG AA 级标准。
- **替代方案**：高对比深色现代 UI 主题（因缺乏古典工坊手工质感被否决）。

### DEC-UI-002: UI 控制器与微模板完全采用 Vanilla JS 解耦装配

- **日期**：2026-10-09
- **状态**：Accepted
- **上下文**：引入 React/Vue 等框架会引入沉重的打包工具链和庞大运行时依赖，且不利于在 Node.js 中执行 0 依赖轻量 Mock DOM 测试。
- **决策**：采用纯原生 ESM、微模板函数 (`layout-templates.js`)、独立控制器与原生 Canvas API。
- **后果**：零框架开销，极速首屏加载，100% 可在 Node.js 中使用 Mock DOM 跑通自动化测试；状态复杂时需由 `AppStore` 精确协调。
- **替代方案**：引入 React 或 Vue 3（因构建包膨胀和 CI 测试环境配置复杂被否决）。

### DEC-UI-003: 七阶段成果采用横向胶片卡片默认折叠呈现

- **日期**：2026-10-10
- **状态**：Accepted
- **上下文**：5 阶段管线加原图与印样共有 7 个中间产物。若全部铺开在主视口，会严重挤占中央高精画布的视觉面积。
- **决策**：将七阶段产物收拢至底部横向胶片栏组件 (`StepFlowGrid`) 中，默认折叠，用户可随时一键展开审查。
- **后果**：兼顾主画面沉浸式大图展示与专业用户对分阶段算法细节的深度检视。
- **替代方案**：多标签页切换查看（无法直观横向比对多阶段演进过程，被否决）。

### DEC-UI-004: 独立无状态 renderEngravedMaster 纯函数与中央母版画布直接同步

- **日期**：2026-10-11
- **状态**：Accepted
- **上下文**：渐进流式分片渲染引入后，中央母版预览画布依赖胶片卡片 Canvas 的 drawImage 间接复制，导致 RAF 异步竞态时母稿经常残缺或空白。
- **决策**：抽离无状态纯函数 `renderEngravedMaster`，中央母版直接由全量矢量数据驱动独立渲染，彻底消除对卡片局部绘制进度的依赖。
- **后果**：中央母稿预览 100% 完整清晰呈现，彻底杜绝残缺、线条缺失或白屏问题。
- **替代方案**：轮询等待卡片 RAF 结束（响应迟钝，容易死锁，被否决）。

### DEC-UI-005: 步骤流线描感知阶段前置度量模型推理耗时与状态机时间角标复位

- **日期**：2026-10-11
- **状态**：Accepted
- **上下文**：`[01] 线描感知` 卡片耗时统计误计为 0.0ms，原因为计时起点置于 AI 网关调用之后；且卡片在进入 COMPUTING 状态时未及时重置隐藏旧时间角标。
- **决策**：在 `PipelineController` 中将阶段 1 计时起点提前至 AI 网关推断之前，记录真实模型推断耗时并传递给 `stepGrid.setStepStatus(1, ..., s1Elapsed)`；`StepFlowGrid` 进入 COMPUTING 时显式隐藏 `timeEl`。
- **后果**：阶段耗时忠实反映神经网络与几何算法真实系统开销，界面状态机交互更为严谨一致。
- **替代方案**：显示固定假数据（违背工程真实性，被否决）。
